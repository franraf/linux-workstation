# 06 — TPM2

## Objetivo

Usar o TPM2 para desbloqueio automático do volume LUKS2 durante o boot validado por Secure Boot, mantendo credenciais independentes para recuperação.

## Pré-condições validadas

- Secure Boot ativo em User Mode;
- boot principal por UKI/systemd-stub;
- UKI e OS medidos;
- LUKS2 funcional por senha;
- backup do header LUKS criado fora do Git;
- segunda credencial LUKS criada antes do enrollment TPM2.

## Estado validado

O dispositivo TPM2 detectado é `/dev/tpmrm0` (`MSFT0101:00`, driver `tpm_tis`). O banco SHA-256 está ativo e o PCR 7 contém a medição da política de Secure Boot.

O volume `/dev/sda2` possui três slots:

```text
SLOT TYPE
0    password
1    password
2    tpm2
```

- slot 0: credencial LUKS original;
- slot 1: credencial independente de recuperação;
- slot 2: token `systemd-tpm2`;
- token TPM2 selado ao PCR 7 no banco SHA-256;
- TPM PIN desabilitado;
- credenciais dos slots 0 e 1 permanecem disponíveis como fallback.

## Política TPM2

Foi adotado PCR 7 (`secure-boot-policy`) em vez de selar diretamente o desbloqueio aos PCRs de conteúdo do UKI.

Objetivo operacional: preservar desbloqueio automático após regenerações normais de kernel/UKI, ao mesmo tempo em que o token permanece associado à política de Secure Boot da máquina.

Mudanças relevantes no estado ou nas chaves de Secure Boot podem invalidar o desbloqueio TPM2; nesse caso deve ser utilizada uma das credenciais LUKS preservadas.

## Enrollment validado

O enrollment foi realizado com `systemd-cryptenroll` usando TPM2 automático e PCR 7. Nenhum keyslot de senha foi removido.

Após enrollment, `systemd-cryptenroll /dev/sda2` confirmou os slots `password`, `password` e `tpm2`, e o header LUKS confirmou token `systemd-tpm2` associado ao keyslot 2.

## Integração com o initramfs

A cmdline canônica contém a opção TPM2 associada ao volume criptografado:

```text
rd.luks.options=<LUKS-UUID>=discard,tpm2-device=auto
```

O UKI é regenerado pelo preset do mkinitcpio e assinado pelo post hook do `sbctl`.

Após alterar a cmdline:

1. regenerar com `mkinitcpio -p linux`;
2. confirmar a nova `.cmdline` dentro do UKI;
3. confirmar `sbctl verify` sem falhas;
4. somente então reiniciar.

## Validação por reboot

O desbloqueio automático foi comprovado por reboot real sem solicitação da senha LUKS.

A validação final foi executada escolhendo explicitamente a entrada UKI. O estado observado foi:

```text
Secure Boot: enabled (user)
Measured UKI: yes
Measured OS: yes
Current Entry: arch-linux-uki.efi
Product: systemd-boot 261.2-1-arch
Product: systemd-stub 261.2-1-arch
```

Portanto, o caminho validado é:

```text
UEFI Secure Boot
  -> systemd-boot
  -> UKI / systemd-stub
  -> sd-encrypt
  -> TPM2 / PCR 7
  -> LUKS2 cryptroot
  -> Btrfs root
```

## Recuperação

- nunca remover simultaneamente os slots de senha em favor do TPM2;
- manter a credencial do slot 1 armazenada independentemente da workstation;
- manter o backup do header LUKS fora do Git e preferencialmente em mídia externa segura;
- se TPM2 falhar após mudança de firmware/Secure Boot, desbloquear com senha e avaliar novo enrollment;
- não apagar ou recriar token TPM2 durante troubleshooting antes de confirmar que uma senha LUKS funciona.

## Validação

```bash
sudo systemd-cryptenroll /dev/sda2
bootctl status
sudo sbctl status
sudo sbctl verify
```

Critérios de PASS:

- slots 0 e 1 continuam `password`;
- slot 2 é `tpm2`;
- Secure Boot permanece ativo;
- boot atual é `arch-linux-uki.efi`;
- systemd-stub está ativo;
- `Measured UKI` e `Measured OS` são `yes`;
- cryptroot desbloqueia automaticamente pelo TPM2;
- assinaturas Secure Boot permanecem válidas.
